# Forte Vision — frontend

Изолированный frontend для ForteBank Datathon 2026. Next.js App Router, React, TypeScript, Tailwind CSS 4, компоненты shadcn/ui на Radix, Lucide. Бэкенд и CV/ML разрабатываются отдельно: их код здесь отсутствует.

## Запуск

Нужны Node.js 22+ и npm. Проверено на Node.js 24.

```bash
cd frontend
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://127.0.0.1:3000. По умолчанию включён деморежим; Go API, ключ и модель не нужны. Шрифт Inter и все демонстрационные материалы хранятся локально, runtime-запросов к CDN и облачным AI нет.

```bash
npm run build
npm run start
```

## Экраны

- `/` — загрузка видео без перехода на другую страницу, последняя задача при её наличии и примеры проверки.
- `/analysis/new` — drag & drop одного `.mov`, валидация, замена и удаление файла. Требования и настройки демосценария раскрываются по запросу.
- `/analysis/[jobId]` — обработка, результат или ошибка. Видео, перемотка, метки событий, кадры и нормативный источник при его наличии.
- `/analysis` — последняя задача этой вкладки и учебные примеры с поиском по имени и фильтром результата; это не серверная история.
- `/analysis/demo-violation`, `/analysis/demo-no_violation`, `/analysis/demo-failed` — постоянные учебные примеры.

Демозагрузка занимает около 7 секунд и ничего не отправляет на сервер. Предустановленные наблюдения **не зависят от содержимого видео**. Кадры — подписанные учебные схемы, не извлечённые из файла. В реальном режиме используются только ответы Go API.

Навигация на компьютере сворачивается; настройка сохраняется локально. На телефоне доступны нижняя панель переходов и выдвижное меню. Композиция основана на Perricheno: светлый холст и отдельная белая рабочая область. Палитра и логотип взяты из предоставленного командой референса ForteBank: графитовый текст, малиновая основная кнопка и приглушённые выделения; бордовый сохранён в бренде. Подробнее — [DESIGN.md](DESIGN.md).

## Подключение Go API

В `frontend/.env.local`:

```dotenv
NEXT_PUBLIC_USE_MOCK_API=false
API_BASE_URL=http://127.0.0.1:8080
API_KEY=your-server-side-key
# При reverse proxy с публичным HTTPS:
# PUBLIC_ORIGIN=https://forte.perricheno.com
```

При reverse proxy укажите точный `PUBLIC_ORIGIN`, если внутренний URL запроса отличается от браузерного origin; произвольные forwarded-заголовки не используются для ослабления проверки POST.

Перезапустите dev-сервер; после изменения `NEXT_PUBLIC_USE_MOCK_API` для production пересоберите приложение. Это публичный флаг режима, а не секрет. `.env.local` исключён из Git.

| Браузер → Next.js       | Next.js → Go API          |
| ----------------------- | -------------------------- |
| `POST /api/analysis`    | `POST /api/v1/analyze`     |
| `GET /api/jobs/{jobId}` | `GET /api/v1/jobs/{jobId}` |

Текущий Go-бэкенд запускается, но CV-процессор пока отключён: реальная загрузка возвращает `503 analysis_unavailable`, а `/readyz` — 503. Демосценарии доступны независимо от модели.

Тонкий proxy передаёт multipart-поток без декодирования видео и добавляет `X-API-Key` **только на сервере**. Поле загрузки — `file`. Секреты не входят в клиентский bundle. Ответы проверяются схемой Zod из `types/analysis.ts`. Это frontend BFF, без очередей, хранения видео, inference или backend бизнес-логики.

Контракт: POST возвращает `{ "job_id": "…" }`. GET возвращает `processing`, `failed` или `done`; для `done` нужны `verdict` (`violation` / `no_violation`) и `violations`. У события есть `type`, `timecode_sec`, `description`, от 1 до 3 кадров `evidence_frames` с `timestamp_sec` и чистым JPEG `image_base64` (без префикса `data:`). Отрицательному результату соответствует пустой массив. Несогласованные и пустые ответы показываются как ошибка.

Поддерживаемые необязательные расширения контракта:

```typescript
// У AnalysisJob:
preview_url?: string; // backend: /api/v1/jobs/{jobId}/preview
warnings?: string[];
certainty?: "suspected" | "insufficient_data" | "limited_scope" | "confirmed";
// У failed:
error?: string | { code: string; message: string };
// У Violation:
certainty?: "suspected" | "insufficient_data" | "confirmed";
classification_status?: "unclassified" | "classified";
regulatory_source?: {
  title: string;
  section?: string;
  url?: string; // HTTPS; только исследованный и подтверждённый источник
} | null;
```

Proxy переписывает только preview текущей задачи с настроенного backend на same-origin `/api/jobs/{jobId}/preview`. При запросе видео он добавляет серверный ключ и передаёт Range/206; произвольные адреса и preview другой задачи отклоняются. Кадры JPEG приходят внутри авторизованного JSON. Ни ключ, ни URL upstream не нужны браузеру. UI показывает `unclassified`, предупреждения и отсутствие достоверности; он не добавляет тип нарушения, уверенность или нормативную ссылку самостоятельно. `no_violation` означает отсутствие срабатывания модели, а не проверку всех нормативных правил.

Polling: последовательно каждые 1,8 секунды, без перекрывающихся запросов; до 3 попыток при временной сетевой ошибке. Для новой загрузки 5 минут считаются с начала POST, включая загрузку; клиент прекращает автоматические повторные запросы после этого срока. На обновлённой странице метаданные сохраняют начало ожидания. Можно повторно запросить ту же задачу. Обязательный общий deadline очереди и inference контролирует backend, который должен вернуть `failed` при превышении 300 секунд; UI-таймер не заменяет это ограничение. Смена страницы отменяет запрос. Искусственного процента выполнения нет. Таймаут POST — 120 секунд, GET — 20 секунд.

## Видео и данные

- Поддерживается один непустой `.mov` до 64 МиБ (67 108 864 байта), в соответствии с лимитом текущего backend. Proxy допускает дополнительно 1 МиБ на multipart-обрамление; окончательный лимит файла проверяет backend.
- MOV — контейнер. Поддержка воспроизведения зависит от кодека. При ошибке оригинала плеер переключается на `preview_url`, если он предоставлен, иначе показывает объяснение.
- Локальное видео доступно через `URL.createObjectURL`. После обновления страницы файл нужно выбрать снова; результат задачи можно получить без повторной загрузки.
- В `sessionStorage` сохраняются только имя, размер, ID и настройки демосценария. Видео, кадры и API-ключ туда не записываются. При запрете storage текущая загрузка продолжает работать в памяти.
- Видео всегда без звука. Идентификации лиц и анализа аудио нет.
- Предустановленная 90-секундная схема в `public/demo/` создана для этого проекта, не содержит банковских данных. Воспроизводится как обычное H.264 MP4. `scene.svg` — её исходник.

## Проверка

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e       # live UI, транспорт API подменён тестовыми ответами
npm run test:e2e:demo  # явная demo-сборка
npm run build          # вернуть live-сборку после demo-тестов
```

E2E использует установленный Google Chrome (`channel: "chrome"`) и production-сборку на порту 3000. Если Chrome отсутствует, установите его или настройте Playwright на свой Chromium. Тесты проверяют загрузку, валидацию, все демосценарии, реальное воспроизведение, переход к таймкоду, модальное окно кадров, перезагрузку, поиск и фильтры, сохранение состояния навигации и адаптивность на 1440 / 1280 / 1024 / 768 / 390 px. Сборка для E2E должна быть в деморежиме: `NEXT_PUBLIC_USE_MOCK_API=true npm run build`. Остановите dev-сервер перед запуском E2E, чтобы тесты использовали эту сборку.

Генератор демонстрационных материалов (не требуется для запуска): `node scripts/generate-demo.mjs /path/to/ffmpeg`. Использует dev-зависимость `sharp` и внешний FFmpeg с libx264. Это геометрическая анимация, без ML.

## Структура и совместная работа

```text
frontend/
  app/              # App Router, layout и тонкий API proxy
  components/       # layout, dashboard, upload, video, violations, ui
  hooks/            # polling с отменой и повторными попытками
  services/         # API client и самостоятельный mock adapter
  types/            # контракт и runtime-валидация
  lib/              # утилиты, память вкладки, серверный proxy
  public/demo/      # собственные учебные материалы
  tests/            # контрактные и браузерные тесты
```

Основная ветка: `main`. Фронтенд изолирован в `frontend/`, Go-бэкенд — в `backend/`. CV может разрабатываться в соседней папке, с независимыми зависимостями и окружением.

## Развёртывание

Нужен Node.js runtime Next.js, поскольку proxy использует серверные секреты; static export не подходит. Публичный хостинг в рамках этой задачи не настроен. Перед production следует настроить HTTPS, лимит тела запроса/таймауты и доступ к интерфейсу через существующий банковский шлюз или VPN. MVP по ТЗ не содержит авторизации и разграничения доступа к задачам; серверный ключ сам по себе этого не обеспечивает. Автоматическая проверка жюри обращается непосредственно к публичным `/api/v1/*` Go API, не к frontend proxy.
