# Forte Vision — frontend

Изолированный frontend для ForteBank Datathon 2026. Next.js App Router, React, TypeScript, Tailwind CSS 4, компоненты shadcn/ui на Radix, Lucide. Бэкенд и CV/ML разрабатываются отдельно: их код здесь отсутствует.

## Запуск

Нужны Node.js 22+ и npm. Проверено на Node.js 24.

```bash
cd frontend
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://127.0.0.1:3000. По умолчанию включён деморежим; FastAPI, ключ и модель не нужны. Шрифт Manrope и все демонстрационные материалы хранятся локально, runtime-запросов к CDN и облачным AI нет.

```bash
npm run build
npm run start
```

## Экраны

- `/` — обзор и примеры сценариев.
- `/analysis/new` — drag & drop одного `.mov`, валидация, замена и удаление файла, выбор демосценария.
- `/analysis/[jobId]` — обработка, результат или ошибка. Видео, перемотка, метки событий, кадры и нормативный источник при его наличии.
- `/analysis` — ссылка на последнюю задачу этой вкладки и учебные примеры; это не серверная история.
- `/analysis/demo-violation`, `/analysis/demo-no_violation`, `/analysis/demo-failed` — постоянные учебные примеры.

Демозагрузка занимает около 7 секунд и ничего не отправляет на сервер. Предустановленные наблюдения **не зависят от содержимого видео**. Кадры — подписанные учебные схемы, не извлечённые из файла. В реальном режиме используются только ответы FastAPI.

## Подключение FastAPI

В `frontend/.env.local`:

```dotenv
NEXT_PUBLIC_USE_MOCK_API=false
API_BASE_URL=http://127.0.0.1:8000
API_KEY=your-server-side-key
```

Перезапустите dev-сервер; после изменения `NEXT_PUBLIC_USE_MOCK_API` для production пересоберите приложение. Это публичный флаг режима, а не секрет. `.env.local` исключён из Git.

| Браузер → Next.js       | Next.js → FastAPI          |
| ----------------------- | -------------------------- |
| `POST /api/analysis`    | `POST /api/v1/analyze`     |
| `GET /api/jobs/{jobId}` | `GET /api/v1/jobs/{jobId}` |

Тонкий proxy передаёт multipart-поток без декодирования видео и добавляет `X-API-Key` **только на сервере**. Поле загрузки — `file`. Секреты не входят в клиентский bundle. Ответы проверяются схемой Zod из `types/analysis.ts`. Это frontend BFF, без очередей, хранения видео, inference или backend бизнес-логики.

Контракт: POST возвращает `{ "job_id": "…" }`. GET возвращает `processing`, `failed` или `done`; для `done` нужны `verdict` (`violation` / `no_violation`) и `violations`. У события есть `type`, `timecode_sec`, `description`, от 1 до 3 кадров `evidence_frames` с `timestamp_sec` и чистым JPEG `image_base64` (без префикса `data:`). Отрицательному результату соответствует пустой массив. Несогласованные и пустые ответы показываются как ошибка.

Необязательные расширения, которые должен подтвердить backend-разработчик:

```typescript
// У AnalysisJob:
preview_url?: string; // браузерный URL H.264 MP4, без API-ключа
// У failed:
error?: string;
// У Violation:
regulatory_source?: {
  title: string;
  section?: string;
  url?: string; // HTTPS; только исследованный и подтверждённый источник
};
```

Предпочтителен same-origin путь для preview либо короткоживущий подписанный HTTPS URL вашего медиасервиса. Preview загружается браузером без секретного заголовка. Backend должен обеспечивать доступ, Range-запросы и корректный Content-Type. UI не добавляет нормативные ссылки самостоятельно.

Polling: последовательно каждые 1,8 секунды, без перекрывающихся запросов; до 3 попыток при временной сетевой ошибке. Через 5 минут ожидание останавливается, можно повторно запросить ту же задачу. Смена страницы отменяет запрос. Искусственного процента выполнения нет. Таймаут POST — 120 секунд, GET — 20 секунд.

## Видео и данные

- Поддерживается один непустой `.mov` до 500 МБ. Это **лимит интерфейса**, его нужно согласовать с backend и reverse proxy; он не является требованием организаторов.
- MOV — контейнер. Поддержка воспроизведения зависит от кодека. При ошибке оригинала плеер переключается на `preview_url`, если он предоставлен, иначе показывает объяснение.
- Локальное видео доступно через `URL.createObjectURL`. После обновления страницы файл нужно выбрать снова; результат задачи можно получить без повторной загрузки.
- В `sessionStorage` сохраняются только имя, размер, ID и настройки демосценария. Видео, кадры и API-ключ туда не записываются. При запрете storage текущая загрузка продолжает работать в памяти.
- Видео всегда без звука. Идентификации лиц и анализа аудио нет.
- Предустановленная 90-секундная схема в `public/demo/` создана для этого проекта, не содержит банковских данных. Воспроизводится как обычное H.264 MP4. `scene.svg` — её исходник.

## Проверка

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2E использует установленный Google Chrome (`channel: "chrome"`) и production-сборку на порту 3000. Если Chrome отсутствует, установите его или настройте Playwright на свой Chromium. Тесты проверяют загрузку, валидацию, все демосценарии, реальное воспроизведение, переход к таймкоду, модальное окно кадров, перезагрузку и адаптивность на 1440 / 1280 / 1024 / 768 / 390 px. Для CI сначала `npm run build`.

Генератор демонстрационных материалов (не требуется для запуска): `node scripts/generate-demo.mjs /path/to/ffmpeg`. Использует dev-зависимость `sharp` и внешний FFmpeg с libx264. Это геометрическая анимация, без ML.

## Структура и совместная работа

```text
frontend/
  app/              # App Router, layout и тонкий API proxy
  components/       # layout, dashboard, upload, video, violations, ui
  hooks/            # polling с отменой и повторными попытками
  services/         # API client и самостоятельный mock adapter
  types/            # контракт и runtime-валидация
  lib/              # утилиты, память вкладки, серверный proxy
  public/demo/      # собственные учебные материалы
  tests/            # контрактные и браузерные тесты
```

Ветка: `feat/frontend`. Все изменения ограничены `frontend/`. Backend и CV могут находиться в соседних папках репозитория, с независимыми зависимостями и окружением.

## Развёртывание

Нужен Node.js runtime Next.js, поскольку proxy использует серверные секреты; static export не подходит. Публичный хостинг в рамках этой задачи не настроен. Перед production следует настроить HTTPS, лимит тела запроса/таймауты и доступ к интерфейсу через существующий банковский шлюз или VPN. MVP по ТЗ не содержит авторизации и разграничения доступа к задачам; серверный ключ сам по себе этого не обеспечивает. Автоматическая проверка жюри обращается непосредственно к публичным `/api/v1/*` FastAPI, не к frontend proxy.
