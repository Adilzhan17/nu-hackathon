FORTE VISION: АРХИТЕКТУРА РАБОЧЕГО КОНТУРА
=========================================

Название подхода: модульный монорепозиторий с выделенным inference-worker.
Не называем систему микросервисной: HTTP-часть и worker разделены для управления
ресурсами, но общая предметная логика находится в одном версионируемом пакете.

1. НАПРАВЛЕНИЕ ЗАВИСИМОСТЕЙ

frontend → HTTP interfaces → application → domain
                  │              ↑
                  └→ infrastructure
inference worker ────────────────┘

domain не импортирует HTTP, GPU, файловые хранилища или обучающие модули.
application использует domain, но не знает адрес GPU и способ HTTP-доставки.
infrastructure реализует извлечение видео и транспорт до worker.
inference запускает локальный llama.cpp и применяет общий application-протокол.
interfaces принимает запросы и соединяет компоненты.

Границы проверяются tests/test_architecture.py. Загрузка рабочего сервиса анализа
не должна импортировать ml.*, torch, transformers или peft.

2. РАСПОЛОЖЕНИЕ КОДА

forte_vision/
  config.py                    конфигурация SSH/GPU, проверка значений
  domain/
    observations.py            типы наблюдений, валидация, память и базовые правила
    scenarios.py               проверки непрерывности и достаточности оснований
    regulations.py             нормативные привязки и применимость
  application/
    analysis.py                протокол окна, оценка наблюдений, покрытие кадров
    detail_selection.py        выбор моментов для детального просмотра
    schema.py                  ограниченная схема ответа модели
  infrastructure/
    gpu_transport.py           PyAV, подготовка кадров, SSH/rsync и контроль worker
  inference/
    gemma.py                   запуск/остановка собственного llama.cpp процесса
    prompts/scenario_v4.txt    текущая инструкция рабочего профиля
  interfaces/
    analysis_http.py           loopback HTTP-сервис сценарного анализа
    jury_http.py               стабильная точка входа API жюри
    review_http.py             стабильная точка входа рабочего места разметки
    _legacy.py                 явная граница оставшихся старых HTTP-модулей

frontend/analysis/index.html — экран сценарного анализа.
frontend/app/demo/gemma/ — совместимый Next.js маршрут к HTTP-сервису.
frontend/lib/gemma-proxy.ts — проверка пути, origin, размера и proxy.
contracts/jury.openapi.json — внешний контракт API, не формат внутренней памяти.
deploy/systemd/ — шаблоны развёртывания с названиями forte-vision-*.

3. ПУТЬ ЗАПРОСА

Обычная веб-загрузка:
  браузер → Next.js /api/analysis?engine=gemma → analysis_http:8771
  → подготовка кадров → собственный GPU-worker → результат → браузер.

API жюри:
  клиент с X-API-Key → /api/v1/analyze → существующий JuryAPI
  → analysis_http с приватным профилем → GPU-worker.
  /api/v1/jobs/{id} отдаёт проверенные результаты по ключу.

Профили и вычислительные лимиты сохранены. Техническая ошибка не превращается
в no_violation. UUID, кадры, подписи данных и сохранённые результаты не меняются.

4. ЧТО СОХРАНЕНО ДЛЯ СОВМЕСТИМОСТИ

Старые модули ml/gemma_lab/{server,runner,protocol,bridge,schema,regulatory,
detail_selection}.py перенаправляют импорт на единственную новую реализацию.
То же сделано для ml/context_pipeline/rules.py и
ml/narration_training/organizer/context.py. Копий исполняемой логики нет.
Старые команды python -m ml.gemma_lab.server и runner продолжают работать.

Сохранённые пути runs/gemma_lab/ и artifacts/gemma_lab/ — формат существующего
хранилища, а не указание на принадлежность к экспериментам. Массовое переименование
нарушило бы историю заданий и проверки происхождения данных, поэтому его нет.

Исторические инструкции в ml/gemma_lab/adaptation/ не переписываются:
они нужны для воспроизводимости. Рабочая копия scenario_v4.txt имеет те же байты;
равенство проверено тестом. Никакого нового обучения или смены весов нет.

5. ИССЛЕДОВАНИЯ И ОСТАВШИЕСЯ ГРАНИЦЫ

ml/gemma_lab/adaptation/ — обучение/оценка Gemma, не вход рабочего сервиса.
ml/human_training/, ml/narration_training/, ml/autolabel/, ml/quality_v2/ —
исследования и подготовка данных. Их нельзя импортировать в новый рабочий пакет.

Разметка, контроллер старых X3D-заданий и реализация JuryAPI пока остаются в ml/.
Для них есть явные интерфейсные адаптеры jury_http и review_http. Это обозначенная
граница миграции, а не утверждение, что весь исторический backend уже перенесён.
Следующее самостоятельное изменение — выделить хранилище заданий и JuryAPI
из legacy-слоя, сохранив контракт и совместимость старых X3D job_id.

Go-backend находится в main/dev/abzal, а не в текущем рабочем запросе.
Его README и реализация отмечают неподключённый Vision. Автоматическое слияние
создало бы два владельца API и разные хранилища. Решение о замене Python gateway
на Go должно быть отдельным, с адаптером реального анализатора и контрактными тестами.

6. ПРАВИЛА ИЗМЕНЕНИЙ

- Новая бизнес-логика — domain/application; сеть и процессы — infrastructure.
- Изменение API начинается с contracts и теста совместимости.
- Новая инструкция — новая версия, без изменения исторического файла.
- Код не читает эталонный ответ видео в рабочем анализе.
- Обучение не активирует checkpoint автоматически.
- Секреты, видео, результаты и веса не коммитятся.
- Имя продукта: Forte Vision. Gemma — реализация модели, не название платформы.

7. ПРОВЕРКА ПЕРЕНОСА (18.10.2026)

Архитектура/конфигурация/контракт: 15 тестов, включая запуск без site-packages.
Рабочий протокол/API/кадры/совместимость: набор63 теста.
Обучение/оценка: набор66 тестов; между наборами возможны пересечения.
Frontend: 20 unit-тестов, отдельный браузерный regression и TypeScript --noEmit.
Публичный мобильный экран: загрузка доступна, удалённого блока нет,
ошибок JavaScript и горизонтального переполнения нет.

На собственном GPU выполнен полный smoke-test новой структуры: знакомое
15,6-секундное TRAIN-видео, 8/8 обзорных кадров, завершение за81,245 секунды.
В результате указан canonical prompt forte_vision/inference/prompts/scenario_v4.txt
и контрольные суммы19 Python-файлов рабочего пакета. Публичный API вернул done.
Это проверка работоспособности переноса, не оценка accuracy и не доказательство
ускорения. Веса, байты инструкции и проверяемые сценарные условия сохранены.
