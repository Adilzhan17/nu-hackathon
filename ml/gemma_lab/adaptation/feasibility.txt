Architecture inspected directly in pinned transformers v5.10.1 source:
Gemma4UnifiedForConditionalGeneration; 48 language layers; hidden size3840;
vocabulary262144. Vision is an encoder-free patch embedder, not SigLIP.
q_proj exists in every language layer. Full-attention layers5,11,...47 have
v_proj=None and reuse key values. The last eight layers have14 q/v modules.
Image processor accepts max_soft_tokens70/140/280/560/1120; use70 per image for
the feasibility pilot. Merely resizing to256 pixels does not impose a token cap.

Training implementation in hf_backend.py:
- Load local files only; caller validates downloaded weights and holds GPU lock.
- NF4 double quantization, FP16 compute, one example with2–4 ordered frames.
- Keep model.embed_vision, model.embed_audio and lm_head out of quantization.
  Vision code casts pixels to patch_dense.weight.dtype: uint8 quantization there
  could corrupt the input before LayerNorm. Assert the initial projection was
  not quantized, then run the small frozen visual embedder in FP32 with AMP
  disabled. Token embeddings remain FP16.
- Freeze base weights, including the tied embeddings. LoRA r4/alpha8 only on
  the14 q/v projections in the final eight language layers.
- Nonreentrant gradient checkpointing. Do not call the generic preprocessing
  helper that promotes all frozen nonquantized weights to FP32. Do not train
  or save the enormous lm_head/embed_tokens modules.
- Answer-only cross entropy uses logits_to_keep=answer_length+1. It excludes
  prompt and image positions, and avoids a full vocabulary projection for them.
- FP16 AMP with GradScaler; skipped nonfinite updates do not count as training.
- Save real adapter_model.safetensors plus exact base, dependency versions,
  target modules and successful update counts. Refuse to save an untrained run.

Memory estimates are not measurements: the tied token embedding alone is
1.875GiB in FP16. The quantized base and nonquantized visual components require
several more GiB, plus activations, logits, allocator overhead and load peaks.
A short 300-second pilot under the shared lock is justified; a full multimodal
fine-tune or a promised accuracy gain is not supported by the current evidence.

Fair comparison: adapter disabled versus enabled on the identical HF NF4 base,
frames, prompt and greedy decoding. NF4 is different from the live llama.cpp
QAT Q4_0 quantization, even though their upstream weights correspond. Do not
attribute cross-runtime differences to adaptation. The live GGUF is unchanged.

CPU validation: four tests cover final-layer selection, assistant-only targets,
token-limit rejection without truncation, and next-token logit alignment. They
do not substitute for the actual GPU training/adapter reload pilot.

Update from the real T4 pilot: the first attempt produced nonfinite loss and
zero updates. A bounded diagnostic found the first nonfinite output in
model.embed_vision.patch_dense: 277 nonfinite outputs despite finite input and
parameters. Input range was approximately -192 to157, weight range -130 to147;
the FP16 output reached65504 before the following normalization. All stored
floating-point parameters passed finite checks. The observed initial allocation
was about7.75GB. This is measured failure evidence, not a successful fine-tune.
The backend now promotes only the small visual embedder to FP32 and disables
autocast inside it, preserving FP32 until its normalization and projection.
A CPU regression test reproduces pre-normalization FP16 overflow and verifies
finite normalized output with this change. The fixed real GPU pilot must still
establish finite loss, actual gradient updates and adapter reload compatibility.
