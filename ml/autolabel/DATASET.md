# Подробный датасет ForteBank

Набор разделяет метки организатора на уровне видео, пользовательские описания, предложения действий, рамки объектов и гипотезы о нарушениях. Все новые артефакты находятся в `data/autolabel/`. Исходные метки и фиксированный train/val не меняются.

| Артефакт | Содержание | Что можно использовать для обучения |
|---|---|---|
| `training_v2/video_bags_train.jsonl` | 32 исходных train-группы: 17 положительных, 15 нормальных; 275 покрывающих окон | Одна метка организатора на целое видео. Все 105 окон положительных видео имеют `interval_target=null` |
| `training_v2/source_windows.csv` | 62 физически экспортированных клипа; ссылки на `training_v1/clips` | 17 окон около положительных отметок — `unknown`; 45 окон нормальных видео сохраняют отрицательную метку исходника |
| `user_pairs_v1/user_video_text_pairs.jsonl` | 99 пользовательских описаний из 13 train-групп | Слабый видео-текстовый надзор; границы приблизительны, пропущенные действия неизвестны |
| `detailed_train/` | 339 окон, кадры, сырые ответы и снимок кода локального Qwen | Исходные данные для проверки предложений, не ground truth |
| `detailed_train_report/` | Действия, эпизоды, состояния объектов, расхождения, очередь и временная шкала | Предложения `proposed`; сильные метки появляются только после человеческого импорта |
| `objects_v1/` | 384 разнообразных кадра исходного разрешения и интерфейс рамок | Сейчас 0 подтверждённых рамок. Обучающий COCO/YOLO экспорт — после человеческой проверки |

`training_v1` сохранён для аудита и физических MP4, но его старые положительные оконные target нельзя использовать как ground truth. `SUPERSEDED.json` и загрузчик блокируют такое использование. В самом старом CSV положительные оконные target также исправлены на unknown; исходная видео-метка вынесена в organizer_video_target. Это исправлено в `training_v2`; исходный `manifest.csv` не редактировался.

## Обучение по метке целого видео

```python
from pathlib import Path
from torch.utils.data import DataLoader, WeightedRandomSampler
from ml.autolabel.video_bags import VideoBagDataset

root = Path('/root/nuhack')
train = VideoBagDataset(root, root/'data/autolabel/training_v2', frames=16, size=224)
sampler = WeightedRandomSampler(train.sample_weights, len(train), replacement=True)
loader = DataLoader(train, batch_size=1, sampler=sampler)
batch = next(iter(loader))
# frames: [1, N_windows, 3, T, H, W]
# video_target: ОДНА метка на исходное видео
# interval_targets: -1 = unknown, 0 = отрицательная метка исходного видео
# interval_label_mask: False для каждого неподтверждённого положительного окна
```

Кодируйте окна небольшими порциями, затем объединяйте признаки/оценки на уровне видео (multiple-instance learning). Loss по положительной метке применяется к результату **всего набора окон**, а не к каждому окну. Загрузчик не выбрасывает случайные окна положительного видео: иначе реальный эпизод мог бы остаться за пределами обучающего примера. Количество окон переменное; для начала используйте batch_size=1. Применяйте нормализацию выбранной архитектуры; загрузчик возвращает [0,1] и letterbox всей сцены.

Отрицательная метка означает только исходный бинарный вердикт организатора. Она не означает отсутствия получения денег, пересчёта или других обычных действий: отрицательные event-labels из неё не создаются.

Вес каждого видео зависит от числа групп его класса. Новых независимых сцен не появилось: train содержит 32 группы, val — 8. Версии и точные дубли исходника имеют общий group_id; Х-4/Х-47 остаются в val, Х-5/Х-48 — в train. Оценку существующих моделей выполняйте на неизменённом frozen manifest, отдельно указывая область исходной метки. Временные границы событий в val этим кодом не создаются.

99 пользовательских пар сохраняют исходные времена, строки и статус. Контекст вокруг отметок не выдаётся за точные границы. Три карантинных наблюдения исключены из обучения; согласие VLM само по себе не меняет их статус.

## Полный локальный анализ

```bash
cd /root/nuhack
bash ml/autolabel/run_detailed.sh detailed_next
```

Первый проход: 2 кадра/с и анализ изменений по всей длительности. Затем окна по 6 секунд с шагом 4 секунды, 4 кадра/с, включая спокойные фрагменты; ещё два окна по 3 секунды на видео с 6 кадрами/с вокруг изменений. Это покрывает последовательности и стыки окон. Для 17 отметок организатора и 3 нормальных контрольных фрагментов выполняется отдельная проверка явно видимых состояний с большим бюджетом разрешения.

Модель: локальная Qwen2.5-VL-7B-Instruct, закреплённый commit `cc594898137f460bfe9f0759e9844b3ce807cfb5`, Apache-2.0 согласно карточке. Карточка и лицензия сохранены в `data/autolabel/`; варианты D-FINE/TEMPURA и их ограничения описаны в [MODEL_CANDIDATES.md](MODEL_CANDIDATES.md).

Скрипт использует только уже выделенный GPU, своё `.venv-autolabel` и общий flock. Пять ограниченных порций: до 80 окон / 450 секунд каждая, внешний timeout 540 секунд. Проверки состояний — до двух порций по 360 секунд с внешним timeout 420 секунд; уже записанные ответы пропускаются. При занятой блокировке прекращает попытку, не трогая чужой процесс; повторный запуск продолжает атомарно сохранённые ответы. Если код инференса поменялся, нужен новый run. Нет бессрочных служб или аренды машин.

Видео, кадры и описания не отправляются облачным AI API. В инференсе используются только локальные веса; аудио не декодируется, личности и персональные реквизиты не распознаются. Отдельная загрузка публичных весов не отправляет пользовательские данные.

## Действия, точные кадры и очередь

`proposals.jsonl` содержит требуемые поля video/group_id/start_sec/end_sec/observed_action/objects/evidence_timestamps/confidence/uncertainty_reason/model_id/model_revision/review_status. Все записи — `proposed`. `confidence` — неоткалиброванная самооценка. Рамок, придуманных из текста, нет.

`moments.jsonl` объединяет только пересекающиеся предложения одинакового действия и набора предметов. `event_details.jsonl` сохраняет описание модели, пути к точным JPEG-доказательствам и их SHA-256. Отсутствующее необязательное описание остаётся пустым с записью в `normalizations.jsonl`; классы и доказательства не дописываются. Недопустимые индексы кадров, предметы и действия отклоняются. Для дополнительного прохода состояний такой же аудит хранится в state_check_normalizations.jsonl: отсутствие необязательного пояснения можно сохранить пустым, но неверное доказательство не исправляется.

`window_analysis.jsonl` содержит описание последовательности каждого окна и ошибки формата. Пустой ответ — воздержание, не отрицательная метка. `parsed_window_coverage_fraction` означает лишь временное покрытие структурно допустимыми ответами, **не recall**.

`user_reference_alignment.jsonl` сопоставляет предложения с оригинальными пользовательскими наблюдениями. Не найденная моделью пользовательская запись остаётся источником более высокого приоритета и попадает на проверку. `conflicts.jsonl` сохраняет карантин и возможные расхождения предметов/направления действий; пересечение может оказаться последовательными или параллельными фазами, поэтому конфликт не разрешается автоматически.

Откройте `data/autolabel/detailed_train_report/index.html` локально. Здесь видео без аудио, временные шкалы, точные кадры-доказательства, исходные отметки и сокращённая очередь до 64 сомнительных интервалов. Полный backlog хранится отдельно. Можно исправить границы и предмет, принять/отклонить предложение или добавить пропущенное действие. Отдельные карточки пользовательских наблюдений предварительно заполняют форму по исходному тексту; подтверждение по видео всё равно обязательно, ссылка на источник сохраняется. Укажите проверяющего и скачайте решения до закрытия вкладки.

```bash
.venv/bin/python -m ml.autolabel.import_reviews \
  --report data/autolabel/detailed_train_report \
  --decisions data/autolabel/review_decisions.jsonl \
  --output data/autolabel/reviewed_actions_v1
```

Импорт создаёт новую версию JSONL/CSV и MP4, проверяет происхождение, границы и train-группы. Подтверждение действия не присваивает ему юридический вердикт. Исходная ручная разметка сохраняется.

## Рамки для детектора

Уже подготовлена очередь `data/autolabel/objects_v1/index.html`: 384 кадра, по 12 на группу, временные страты и разнообразие изображения. Отбор не доказывает присутствие редких классов и не гарантирует их баланс.

```bash
.venv/bin/python -m ml.autolabel.object_frames prepare \
  --run data/autolabel/detailed_train --output data/autolabel/objects_next
```

Классы: cash, document_id, key, stamp. Рисуйте рамки только по реальной видимости. Похожий/неразличимый предмет помечайте uncertain; перекрытый, но различимый — partly_occluded. Масштаб просмотра не меняет исходные координаты. Для отрицательного примера требуется явно завершить просмотр всего кадра и подтвердить отсутствие целевых объектов. Непросмотренные изображения не являются background.

```bash
.venv/bin/python -m ml.autolabel.object_frames import \
  --source data/autolabel/objects_v1 \
  --decisions data/autolabel/object_decisions.jsonl \
  --output data/autolabel/reviewed_objects_v1
```

Экспорт создаёт `coco_train.json`, `images/`, YOLO `labels/`, `train.txt`, классы, принятые и отложенные решения. Только полностью проверенные кадры с надёжными классами попадают в обучение. Кадр с хотя бы одним uncertain-объектом исключается целиком, чтобы не превратить неразмеченную область в background. Val-набор рамок не создаётся и не подменяется train-изображениями. Для сравнения детекторов потребуется отдельная подтверждённая оценка при сохранении фиксированных групп.

## Гипотезы о нарушениях

`incident_candidates.jsonl` содержит **контекст исходной положительной видео-метки**, `interval_target=null`. Это не положительные интервальные метки. `visual_state_proposals.jsonl` — предположения о видимых состояниях. `risk_pattern_candidates.jsonl` требует положительных свидетельств состояния по обе стороны ухода работника. Отсутствие метки закрытия сейфа не означает, что сейф открыт.

`rule_definitions.json` и `rule_assessments.jsonl` отделяют проектные шаблоны проверки от нормативного вывода. Статус — `insufficient_data` либо `requires_visual_and_rule_review`; `legal_violation_target=null`. Проверка отсутствия этапа контроля банкнот требует подтверждённых границ операции, полной видимости нужного этапа, отсутствия перекрытий, явного человеческого подтверждения отсутствия и применимости правила. Текущий VLM этих условий не подтверждает, поэтому пропуск его аннотации не образует нарушение.

## Проверки

```bash
.venv/bin/python -m unittest discover -s ml/autolabel -t . -p 'test_*.py' -v
.venv/bin/python -m ml.autolabel.validate_dataset
```

Проверяются PTS, границы, происхождение кадров, отсутствие аудио в экспортах, frozen train/val, дубли, запрет положительных псевдометок окон, явные человеческие решения, рамки и неопределённость. Результаты проверок и реальные числа сохраняются в `data/autolabel/validation_report.json` и summary соответствующих наборов. Precision/recall и качество обнаружения нарушений без независимой проверки не заявляются.
