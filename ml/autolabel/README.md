# Локальные предложения разметки ForteBank

Текущий подробный набор, обучение по метке целого видео, интерфейсы действий/рамок и команды экспорта описаны в [DATASET.md](DATASET.md). Ниже сохранён протокол первоначального пилота. Старый `training_v1` заменён `training_v2`: неподтверждённые положительные интервалы имеют статус unknown.

Отдельный пайплайн для **наблюдаемых действий**, без юридических вердиктов. Записывает только `data/autolabel/`; не изменяет исходную ручную разметку, manifest, сервер или обучение. Не создаёт ground truth и не подключён к `train_suite.py`.

## Запуск готового пилота

Из `/root/nuhack`:

```bash
bash ml/autolabel/run_pilot.sh pilot_next
```

Имя запуска должно быть новым. По умолчанию: `videos/Х-21.mov`, `videos/Х-22.mov`, `videos/Х-5.mov`, по три кандидатных окна на видео. Можно передать другие **train**-видео после имени запуска. Скрипт использует существующий GPU, отдельную `.venv-autolabel`, ключ непосредственно через SSH и общий `/home/ubuntu/nuhack-training/.gpu-work.lock`. Ключ не копируется. Ожидание блокировки ограничено 30 секундами, GPU-команда — 600 секундами. Существующие процессы не останавливаются. Новые машины не создаются.

Первичная настройка отдельного окружения на существующем GPU (для текущего пилота уже выполнена):

```bash
cd /home/ubuntu/nuhack-training
python3 -m venv .venv-autolabel
.venv-autolabel/bin/pip install --upgrade pip
.venv-autolabel/bin/pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
.venv-autolabel/bin/pip install -r ml/autolabel/requirements.txt
.venv-autolabel/bin/python -m ml.autolabel.download_model \
  --destination data/autolabel/models/qwen2.5-vl-7b
```

Загрузка модели — отдельный сетевой шаг, который не читает данные. Во время инференса: только локальные веса, `local_files_only=True`, `trust_remote_code=False`, отключены Hub/Transformers network access и телеметрия. Нет облачных AI-клиентов, обработки аудио, распознавания личностей или OCR персональных реквизитов. Кадры переносятся только на указанный пользователем вычислительный узел и не передаются сервисам AI API.

Для полностью изолированного контура заранее перенесите окружение, код и каталог весов с `autolabel_model_lock.json`. Инференс не требует Hugging Face-токена или доступа к сети. Основные команды, если данные и GPU находятся на одной машине:

```bash
python -m ml.autolabel.pipeline prepare --run data/autolabel/new_run \
  --videos videos/Х-21.mov videos/Х-22.mov videos/Х-5.mov
python -m ml.autolabel.pipeline infer --run data/autolabel/new_run \
  --model-path data/autolabel/models/qwen2.5-vl-7b \
  --gpu-lock /home/ubuntu/nuhack-training/.gpu-work.lock
python -m ml.autolabel.pipeline finalize --run data/autolabel/new_run
python -m ml.autolabel.pipeline validate --run data/autolabel/new_run
python -m unittest ml.autolabel.test_autolabel -v
```

Без `--videos` подготовка охватывает все train-группы, по одному представителю группы. **Не запускайте полный набор до оценки пилота и бюджета.** На локальном CPU для подготовки и проверки достаточно PyAV, NumPy, Pillow и OpenCV; существующая `.venv` workspace уже содержит их. GPU-окружение полностью отдельное.

## Два этапа и ограничения времени

1. Полный визуальный проход по выбранному видео на 1,5 кадра/с. Средняя разность сглаженных кадров выявляет изменения. Это селектор движения, а не классификатор действий.
2. Два окна с сильными изменениями и одно окно с малым движением: последнее снижает риск полностью игнорировать спокойные действия за столом. Окна по 4 секунды, ограничение регулируется `--max-candidates` и `--window`. Это ограниченный пилот, не исчерпывающий поиск.
3. Внутри окна — 4 кадра/с, хронологическая последовательность с фактическими PTS. VLM получает все кадры окна и их абсолютные секунды. Ручные описания и исходный вердикт модели не подсказываются.
4. Принимаются события с минимум двумя реально показанными кадрами, разнесёнными во времени. `start_sec`/`end_sec` — границы свидетельств модели, а не доказанные точные начало/конец действия. Фальшивые таймкоды, одиночные кадры, некорректные категории и рамки отклоняются.
5. Пустой ответ — воздержание, а не отрицательная метка. Некорректные ответы и воздержания также попадают в очередь. Соседние сомнительные интервалы объединяются, добавляется контекст ±2 секунды. Локальные MP4-превью перекодируются через PyAV без аудио.

## Модель и лицензия

Используется **Qwen/Qwen2.5-VL-7B-Instruct**, revision `cc594898137f460bfe9f0759e9844b3ce807cfb5`.

- [Закреплённая карточка весов](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct/blob/cc594898137f460bfe9f0759e9844b3ce807cfb5/README.md) явно указывает `license: apache-2.0`. Apache-2.0 допускает коммерческое использование с соблюдением её условий.
- В репозитории этих весов нет отдельного файла LICENSE. Основание выбора — лицензионная декларация карточки **7B**; её копия и SHA-256 сохранены. Текст Apache-2.0 сохранён из [официального репозитория реализации](https://github.com/QwenLM/Qwen2.5-VL/blob/main/LICENSE), источник различается явно.
- Рассмотрена [SmolVLM2-2.2B-Instruct](https://huggingface.co/HuggingFaceTB/SmolVLM2-2.2B-Instruct): меньше расход памяти, также заявлена Apache-2.0. Для доступного GPU выбран Qwen7B с поддержкой последовательностей изображений и структурированных ответов. Это инженерный выбор, не результат сравнительной оценки на наших видео.
- Лицензия 3B не предполагается равной лицензии 7B. Версии не заменяются автоматически.

VLM предлагает названия предметов, но не измеряет рамки объектов. Поэтому **координат нет**. Обычный COCO-детектор не заменяет специализированное распознавание денег, ключей, печатей и сейфа. Этот модуль не заявляет, что обучил такой детектор; предложения классов помогают собрать будущую ручную разметку. Модель может путать бумагу с деньгами, шкаф с сейфом и маленький предмет с ключом. Невидимость предмета не доказывает его отсутствие или нарушение.

## Источники и защита выборок

- Manifest считается зафиксированным. Все 42 исходных файла проверены SHA-256: 40 групп, train=32, val=8.
- Х-4 / Х-47 — общая **val**-группа; Х-5 / Х-48 — общая **train**-группа. На val предложения не генерируются. Дубли не дают дополнительных независимых примеров.
- Неизвестный файл не получает случайный split. Для нового перекодирования задайте JSON `{"videos/derived.mp4":"videos/original.mov"}` через `--lineage` на prepare/finalize/validate. Любая связь, противоречащая frozen manifest, останавливает выполнение. Manifest не исправляется автоматически.
- SHA-256 не находит все похожие постановочные сцены или неизвестные перекодировки. Связь версий должен явно сообщить владелец данных. Для обрезанных/ускоренных версий также нужна отдельная ручная проверка времени: одинаковый group_id не означает одинаковые таймкоды.
- Организаторские бинарные вердикты сохранены как контекст, отдельно от действий. `cash_received` при «без нарушения» **не является конфликтом**.
- `sources.json: mapping=user_confirmed` означает подтверждение связи фрагмента расшифровки с видео. Оно **не** означает проверенных покадровых границ. Все исходные наблюдения сохраняются, никаких исправлений по ответу VLM нет.
- Три `quarantined` наблюдения не используются как достоверные метки и не передаются модели. Они сохраняются в `conflicts.jsonl` как нерешённые вопросы источника.
- Проверка возможных противоречий консервативна: открытие/закрытие сейфа, направления передачи денег и разные названия предмета в пересекающихся интервалах взаимодействия. Это сигналы для проверки, поскольку действия могут быть последовательными фазами или происходить одновременно. Проверка не обнаруживает все смысловые противоречия.

## Артефакты и работа проверяющего

В каждом запуске:

- `plan.json`, `scan_*.json`, `frames/*.jpg`: registry, версии входных файлов, кандидатные интервалы, фактические таймкоды и SHA-256 кадров.
- `proposals.jsonl`: строгая схема `ml/autolabel/proposal.schema.json`; все строки имеют `review_status="proposed"`. `confidence` — **неоткалиброванная самооценка модели**, не вероятность.
- `raw_responses.jsonl`, `rejected.jsonl`: исходные ответы и причины отказа валидатора. JSON-массив событий допускается как эквивалент оболочки `{"events":[...]}`; текстовые ответы не «ремонтируются», категории и таймкоды не выдумываются.
- `conflicts.jsonl`: карантин источников и возможные противоречия с оригинальными/пользовательскими наблюдениями.
- `review_queue.jsonl`, `review.html`, `context/*.mp4`: только сомнительные, противоречивые или неразрешённые интервалы. Откройте HTML локально; внешних скриптов и запросов нет.
- `inference.json`, `inference_code/`: параметры, время GPU-команды, ревизия модели и снимок кода инференса (начиная с `pilot_v3`).
- `summary.json`: числа предложений, конфликтов, видео и ограничений.

Человеку нужно проверить видимость предметов, направление и последовательность действия, затем уточнить границы. Сохраняйте решение отдельно от предложения и исходной разметки. Интерфейс просмотра не выдаёт автоматического принятия меток; прямого экспорта в обучение нет. Высокая самооценка модели тоже не делает предложение ground truth. При ограниченной очереди остальные предложения остаются неподтверждёнными в JSONL.

Все результаты пилота — проверка работоспособности и ограничений, **не измерение precision/recall**. Для оценки качества нужны независимо подтверждённые события и отдельный протокол, без настройки на val.

## Результат выполненного пилота

Итоговые артефакты: `data/autolabel/pilot_final/`; открыть `review.html`.

- 3 train-видео, 170 кадров первого прохода, 9 кандидатных окон, 153 кадра второго прохода.
- 4 предложения, покрыты 3 видео; 4 записи в conflicts: 3 исходных quarantined и 1 возможное расхождение предмета.
- 7 объединённых интервалов проверки с контекстом; 5 окон с воздержанием VLM. Ground truth: 0 новых записей.
- Последний GPU-инференс: 26,432 секунды; три отладочных GPU-прогона суммарно 110,147 секунды (загрузка весов/настройка и время работы общей VM сюда не входят).
- 12 автоматических тестов прошли. Реальные артефакты проверены на формат, таймкоды, SHA-256 кадров, группировку, train-only и неизменность четырёх исходных файлов разметки. Все 7 MP4 декодируются и не имеют аудиотреков.

На проверку особенно важны: Х-21, 6–10 с — модель предложила документы, а подтверждённый пользователем источник описывает работу с деньгами в пересекающемся времени; Х-22, 9,93–10,67 с, и Х-5, 56–59 с — гипотезы о ключах. Х-21, 13,33–17,33 с — предложение пересчёта денег с самооценкой 0,8, оставлено неподтверждённым в JSONL вне сокращённой очереди. Карантин Х-5 на 65–70 с требует разрешения исходной привязки к видео.

Сохранена история: `pilot` (1 предложение, 8 отказов валидатора), `pilot_v2` (0 предложений), `pilot_v3` (4 предложения). Во втором варианте вместе менялись разрешение и дополнительная инструкция; эффект каждого изменения отдельно **не измерен**. `pilot_final` повторно использует инференс `pilot_v3`, добавляя проверку расхождения предметов без нового GPU-прогона. Все результаты являются диагностическими, а не оценкой точности модели.
