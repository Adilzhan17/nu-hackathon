# ForteBank backend

Go-бэкенд для Datathon 26: HTTP API, проверка ключа, потоковая загрузка, сохранение заданий в bbolt, ограниченная очередь и фоновые workers. Структура сохранена: controllers → services → интерфейсы repositories/processors; зависимости собираются менеджерами.

**CV-модель ещё не подключена.** Сервер запускается, но `POST /api/v1/analyze` возвращает `503 analysis_unavailable`, не сохраняет видео и не создаёт фиктивный результат. `/readyz` тоже возвращает 503. Успешная обработка станет доступна после реализации настоящего локального анализатора.

## Запуск

Требуется Go 1.25 или новее. Из папки `backend`:

```powershell
Copy-Item .env.example .env
# В .env задайте собственный API_KEY длиной не менее 16 байт.
go run .
```

Приложение читает необязательный `.env` из текущего каталога; переменные окружения имеют приоритет. Поддерживаются строки `KEY=value` и значения в кавычках, без подстановок shell. Без подходящего `API_KEY` запуск завершается ошибкой. Реальный ключ хранится только локально, `.env` исключён из Git.

Адрес по умолчанию — **http://127.0.0.1:8080**. Проверка работающего процесса:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/healthz
```

Остановка — `Ctrl+C`: сервер прекращает принимать запросы, останавливает workers и закрывает БД. Задания хранятся в `storage/jobs.db`, загруженные видео — в `storage/videos`.

## API и Swagger

| Метод и путь | Назначение | Авторизация |
| --- | --- | --- |
| `POST /api/v1/analyze` | Один MOV в multipart-поле `file`; при доступном анализаторе ответ 202 с `job_id` | `X-API-Key` |
| `GET /api/v1/jobs/{job_id}` | Статус `processing`, `done` или `failed` и результат | `X-API-Key` |
| `GET /healthz` | Работа HTTP-процесса: 200, `{"status":"ok"}` | Нет |
| `GET /readyz` | Готовность БД и анализатора: 200 `ready` или 503 `not_ready` | Нет |
| `GET /openapi.yaml` | Встроенная в сборку спецификация | Нет |

Источник контракта — [docs/openapi.yaml](docs/openapi.yaml). Swagger UI запускается отдельно:

```powershell
docker compose up -d swagger
```

Открыть **http://localhost:8081**, нажать **Authorize**, ввести API-ключ и использовать **Try it out**. Go-сервер должен быть запущен отдельно. CORS разрешён для двух локальных адресов Swagger. Авторизация не сохраняется между перезагрузками UI, внешний валидатор выключен. Нужен работающий Docker Desktop с Linux containers; при первом запуске загружается образ.

```powershell
docker compose config --quiet
docker compose down
```

Compose поднимает только Swagger. После изменения спецификации приложение нужно пересобрать или перезапустить через `go run .`, чтобы обновить встроенный `/openapi.yaml`.

## Подключение существующего фронта

В локальной конфигурации фронта нужно установить:

```dotenv
API_BASE_URL=http://127.0.0.1:8080
API_KEY=<тот же приватный ключ, что у бэкенда>
NEXT_PUBLIC_USE_MOCK_API=false
```

Затем перезапустить Next.js. `API_KEY` используется серверным proxy Next.js, не должен иметь префикс `NEXT_PUBLIC_` и не передаётся в браузер. До подключения CV реальная загрузка получит 503; демонстрационные результаты фронта не являются результатами этого API.

При `failed` поле `error` — безопасная строка, как ожидает существующий фронт. HTTP-ошибки имеют отдельный формат `{ "error": { "code": "...", "message": "..." } }`. Для нарушений предусмотрен `regulatory_source` с названием, необязательными разделом и HTTPS-ссылкой. Это расширение ответа для UI; обязательные поля жюри сохранены. `preview_url` сервер пока не выдаёт.

## Архитектура и хранение

Используется стандартный `net/http`. Managers создают и переиспользуют зависимости через `sync.Once` внутри одного контейнера приложения. Это singleton на время жизни контейнера; глобального изменяемого контейнера нет. Clean Architecture задаёт направление зависимостей, а singleton — время жизни экземпляра. Сервисы получают необходимые интерфейсы через конструкторы; HTTP, файловая система и bbolt не становятся частью бизнес-моделей.

Один процесс содержит HTTP-сервер и workers. bbolt сохраняет задания и результаты в локальный файл и блокирует его от одновременного открытия вторым процессом. Очередь находится в памяти и ограничена по размеру. После перезапуска незавершённые задания переходят в `failed`: автоматического повторного анализа нет. Схема рассчитана на один экземпляр приложения; горизонтальное масштабирование потребует другого хранилища и очереди.

Исходное видео удаляется после завершения или сбоя задания. Результаты и доказательные кадры хранятся 24 часа по умолчанию, затем удаляются периодической очисткой; после очистки GET возвращает 404. Свободные страницы bbolt переиспользуются, но размер файла автоматически не уменьшается. Удаление записи не гарантирует физическое стирание её прежних байтов на носителе.

## Лимиты и настройки

Все значения ниже — решения реализации, а не дополнительные требования организатора. Параметры перечислены в [.env.example](.env.example).

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_ADDR` | `127.0.0.1:8080` | Адрес API |
| `LOG_LEVEL` | `info` | Уровень журналирования |
| `STORAGE_DIR` | `./storage` | Локальные данные |
| `UPLOAD_MAX_BYTES` | `524288000` | 500 MiB на файл, как в текущем фронте |
| `UPLOAD_TIMEOUT` | `110s` | Время приёма загрузки |
| `ANALYSIS_TIMEOUT` | `270s` | Общий бюджет от начала загрузки, включая очередь |
| `SHUTDOWN_TIMEOUT` | `15s` | Бюджет штатной остановки |
| `WORKERS` | `1` | Параллельные анализы |
| `QUEUE_SIZE` | `8` | Задания, ожидающие worker |
| `MAX_UPLOADS` | `2` | Одновременные загрузки |
| `JOB_RETENTION` | `24h` | Срок хранения результатов |
| `CLEANUP_INTERVAL` | `10m` | Интервал очистки |
| `CORS_ORIGINS` | `http://localhost:8081,http://127.0.0.1:8081` | Разрешённые браузерные origin |

Полный multipart-запрос ограничен размером файла плюс 1 MiB служебных данных. Загрузчик проверяет структуру контейнера MOV, включая блоки `moov` и `mdat`; декодирование кодека ещё не реализовано. Переполненная очередь или недоступный анализатор дают 503.

На результат допускается до 32 событий, по 1–3 настоящих JPEG на событие; один кадр — до 1 MiB и 4096 пикселей по каждой стороне, суммарно кадры — до 16 MiB до base64-кодирования. Перед сохранением проверяются вердикт, согласованность списка событий, времена, JPEG и наличие источника для каждого нарушения. Проверка структуры не подтверждает содержание кадра или достоверность нормативной ссылки — это задача алгоритма и проверки правил.

## Подключение CV

Граница интеграции — интерфейс `processors.Vision` с методами `Available` и `Analyze(ctx, path)`. Вместо отключённого процессора нужно внедрить локальную реализацию в контейнер. Она обязана соблюдать отмену и deadline контекста, использовать только видеоряд и возвращать реальные кадры и проверяемые объяснения. Для отдельного процесса инференса потребуется управляемая остановка процесса при отмене.

`no_violation` допустим только после успешного анализа. Отсутствие модели, технический сбой, некорректный результат и истечение времени не превращаются в этот вердикт. Каталог событий, модель, декодер и проверенные нормативные правила ещё предстоит выбрать. Точность, реальное время обработки и соблюдение общего лимита жюри в 5 минут нужно измерить на целевом оборудовании.
