# Требования к бэкенду ForteBank

Источник: предоставленный пользователем файл `Кейс_ForteBank.docx`, разделы 1–10 и FAQ. Ниже отдельно приведены требования кейса и решения команды. HTTP API, хранение и очередь реализованы; настоящий CV-анализ ещё не подключён.

## Обязательный сценарий

1. Пользователь загружает видео через UI; жюри загружает его через API.
2. Сервис возвращает идентификатор задания и обрабатывает видео в фоне.
3. Клиент получает статус `processing`, `done` или `failed`.
4. При завершении возвращается `no_violation` либо `violation`.
5. Каждое возможное нарушение содержит тип, таймкод в секундах, описание наблюдаемого действия и 1–3 JPEG-кадра в base64.
6. Пользователь видит правило и нормативный источник: название, пункт/раздел, ссылку при наличии.

Схема для жюри сохранена в [openapi.yaml](openapi.yaml). Техническая ошибка не превращается в `no_violation`: для неё есть `failed`.

## Данные и ограничения

| Область | Требование из кейса |
| --- | --- |
| Видео | `.mov`, около 29 МБ; длительность 10–145 с; FPS от 29 |
| Датасет | минимум 40 постановочных роликов; одна камера сверху, одна касса |
| Разметка | метка наличия нарушения и таймкод; без типа события |
| Обобщение | возможны новые типы событий; финальный ракурс отличается |
| Время | результат за 5 минут; иначе видео считается необработанным |
| Инференс | только локальные модели; после загрузки весов интернет для анализа не нужен |
| Запреты | облачные AI API, передача им видео/кадров/описаний, звук, идентификация лиц |
| Вывод | признаки возможного нарушения для проверки человеком; без выводов о невидимых операциях |
| Источники | публичные акты РК, НБРК, adilet.zan.kz; связь правила с наблюдаемым событием |
| Сдача | публичные URL UI/API, ключ жюри, инструкция, архитектура, перечень типов и ограничений |

Длительность, FPS и размер около 29 МБ описывают датасет, а не обязательные основания для отказа в загрузке. Тестовые видео нельзя использовать для обучения, публиковать или передавать третьим лицам. Данные используются только в рамках хакатона. Текущая реализация удаляет исходное видео после завершения или сбоя задания; результаты и кадры удаляются периодически по настроенному сроку хранения, по умолчанию 24 часа.

Авторизация пользователей, история, экспорт и пакетная загрузка не обязательны. Ключ `X-API-Key` для API жюри обязателен. GPU и облачные кредиты организатор не предоставляет.

## Решения текущей реализации

- Успешное создание задания: HTTP 202; опрос: HTTP 200.
- Ошибки API: `{ "error": { "code": "...", "message": "..." } }`; диагностическая ошибка задания — необязательная строка `error` при `failed`, совместимая с текущим фронтом.
- Максимальный размер файла по умолчанию: 500 MiB, как в текущем фронте; 29 МБ из ТЗ — ориентир размера ролика, не точный предел. На служебную часть multipart дополнительно допускается 1 MiB.
- Общий бюджет анализа: 270 с от начала загрузки, включая ожидание в очереди. Приём загрузки ограничен 110 с. Соблюдение общего предела жюри в 5 минут потребует замера реального сценария после подключения модели.
- Тип события — свободная строка: категории ещё не определены.
- Правило и его связь с наблюдаемым действием — в `description`. Для структурированного показа источника во фронте добавлено `regulatory_source` с названием, необязательными разделом и HTTPS-ссылкой. Обязательные поля JSON жюри сохранены. Публичные нормы собраны в [нормативном каталоге](regulatory-catalog.md), список источников и необходимых данных — в [карте охвата](regulatory-coverage.md). Применимость зависит от вида операции, условий и редакции на дату съёмки; исчерпывающий правовой охват не заявлен. К анализатору каталог пока не подключён.
- Задания сохраняются в локальной bbolt, очередь ограничена и находится в памяти одного процесса. После перезапуска незавершённые задания получают `failed`.
- Ограничения результата: до 32 событий, по 1–3 JPEG на событие, до 1 MiB на кадр и 16 MiB на все кадры до base64. Эти пределы выбраны командой.

Сервер реализует инфраструктуру загрузки, заданий и обработки. Пока CV-процессор не подключён, загрузка возвращает `503 analysis_unavailable` без сохранения видео и создания задания. Тестовые анализаторы применяются только в тестах; фиктивных успешных вердиктов в рабочем API нет. Актуальные параметры запуска и границы реализации: [../README.md](../README.md).

## Неоднозначности задания

- FAQ упоминает вердикт «Недостаточно данных», но раздел 10 разрешает только `no_violation` и `violation`. В API оставлены ровно два значения. Порядок работы с неразборчивым видео нужно согласовать; `failed` предназначен для технического сбоя обработки.
- FAQ разрешает open source и предобученные модели с коммерчески допустимой лицензией, но также говорит о дисквалификации за «готовые решения». Референсы используются для изучения подходов; допустимость конкретной готовой системы нужно уточнить у организатора.
- Основной текст требует пункт/раздел нормативного источника; FAQ допускает ссылки без точного пункта. При исследовании следует стремиться к точному пункту, не выдумывая ссылок.
- Не заданы кодеки внутри MOV, параллелизм, частота опроса, TTL результатов и точный формат ошибок. Они не выдаются за требования организатора.
