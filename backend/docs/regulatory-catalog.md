# Нормативный каталог для анализа кассовых операций

Дата проверки источников: **17.10.2026**. В каталоге **210 карточек требований, условий и исключений**.

Назначение: связывать наблюдаемое событие с конкретным пунктом публичного нормативного акта. Каталог относится к кассовым операциям банков второго уровня, устройству кассовых помещений, обращению с наличными и обмену иностранной валюты. Это исследовательские данные для команды; анализатор их пока не использует.

Сохранены полные текстовые выгрузки **41 официального акта**, включая основные кассовые правила, связанные законы и отдельные изменяющие акты; дополнительно сохранены две исторические выдержки для проверки №207/208. Для не полностью обновлённых сводных текстов указаны необходимые поправки. Таблицы ниже — разбор применимости норм, а не замена оригинального текста. **Исчерпывающий охват всех юридических обязанностей ForteBank не установлен:** отдельные требования зависят от операции, других законов, договоров и внутренних документов банка. Полнота нормативной базы и число реализованных видеодетекторов — разные характеристики.


**Навигация:** [полный перечень источников и границы охвата](regulatory-coverage.md), [необходимые данные команды/банка](regulatory-coverage.md#что-нужно-получить-от-команды-и-банка), [манифест версий](regulations/sources.json), [индекс прямых ссылок](regulations/cross-reference-index.json).

## Как читать каталог

- **Видео + контекст**: видимые события полезны, но нужно подтвердить вид операции, границы зоны, роль участника и исключения.
- **Документы / система**: требуются журнал, кассовый документ, данные операции, полномочия либо договор. Движение рук и работа за компьютером не подтверждают содержание этих данных.
- **Осмотр / экспертиза**: требуются характеристики оборудования, измерения помещения либо исследование банкнот. Обычная верхняя камера этого не заменяет.

Во всех строках «пункт» относится к **Правилам, утверждённым постановлением**, если явно не сказано иное. Номер статьи закона и номер пункта Правил не взаимозаменяемы.

## Правила, которые нельзя придумывать по бытовому описанию

Статьи УК не подставляются автоматически вместо процедурного правила. В частности, [статья 189 УК](https://adilet.zan.kz/rus/docs/K1400000226) относится к присвоению/растрате вверенного чужого имущества; правовая квалификация требует установления обстоятельств, которые движения денег на видео сами не доказывают. [Разъяснение Верховного Суда о хищениях](https://adilet.zan.kz/rus/docs/P03000008S_). Для системы кейса формулировка — наблюдаемые признаки возможного нарушения с проверяемым процедурным основанием.

## Что ещё требуется для полного реестра применимости

1. Основные связанные блоки ПОД/ФТ, валюты, чеков, охраны, пожарной безопасности и данных добавлены выше. Продолжать проверку зависимостей по конкретному сценарию: формы/признаки сообщений финмониторинга, дистанционная идентификация, защита потребителей, технические и отраслевые стандарты. Все статьи больших законов и рекурсивные отсылки не разобраны; подробные границы — в [карте охвата](regulatory-coverage.md).
2. Получить разрешённые к использованию внутренние правила банка: границы зон, роли/допуски, движение денег и ключей, порядок хранения, смены и передачи ответственности. Не пытаться найти конфиденциальные внутренние документы в публичных источниках.
3. Привязать наблюдаемые действия из обучающих видео к строкам каталога. Отдельно отметить события без найденного нормативного основания; не назначать им случайную статью.
4. Для каждого детектора проверить полный эпизод, исключения, видимость и альтернативные объяснения. Необнаружение действия на обрезанном/перекрытом фрагменте не доказывает его отсутствие.
5. Перед включением правила зафиксировать редакцию, интервал действия и проверяющего. Перед демонстрацией повторно сверить изменения официальных источников; текущие файлы являются снимком, а не автоматически обновляемой правовой системой.

## Связь с результатом API

Для будущей карточки проверки нужны: стабильный `rule_id`, вид операции, субъект, пункт/подпункт, точный исходный текст, простое описание, условия/исключения, наблюдаемые признаки, необходимые внешние подтверждения, источник и версия. Полнота доказательств хранится отдельно от уверенности модели в распознанном действии.

Пример объяснения: «На 00:18 сотрудник покидает размеченную рабочую зону во время продолжающегося обслуживания клиента; возможное несоблюдение пункта 22 Правил, утверждённых постановлением НБРК №231 от 29.11.2019». Такое объяснение допустимо только после проверки указанного контекста; сам пример не является разметкой реального видео.

В существующем API название, пункт и ссылка размещаются в `regulatory_source.title`, `regulatory_source.section` и `regulatory_source.url`; наблюдение и связь с нормой — в `description`. Идентификатор правила и версия могут храниться внутри будущего анализатора. Контракт API и его статусы этим документом не изменены; вопрос недостаточной видимости из FAQ остаётся отдельно отмечен в [requirements.md](requirements.md).
